Outcomes:
1. Define the stages of the product lifecycle. These do not need to be linear. This should also include the processes for CRIs and bugs. 
2. Create the first version of the quality gates that begin each stage of the process.
3. Define where the inputs and outputs to each process live. (Teams, figma, Linear/Jira/Issues, github, production, posthog, etc)
4. As needed, define how the work gets done for that process. I.e. backlog grooming meetings, ticket templates, etc.

Defining the process
1. Define the input into the process.
2. Quality gate for accepting input into the process. (Including rework)
3. Rules for prioritizing work in the process. (Frozen window)
4. Define how the work is done. (If necessary)
5. Define the output of the process. (Input into the next process)
6. Define how to determine output quality. (Quality gate of the next process)

How do we get back on track when things get derailed?
1. Start having regular process meetings again.
2. Start enforcing the quality gates again.
3. Try to build the exceptions into the process. Use prioritization tradeoffs, etc.
